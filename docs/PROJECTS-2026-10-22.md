# Project showcase: unified layout and explanatory motion

Date: 2026-10-22 (America/Asuncion). Local implementation following the owner's
screenshots and feedback. No commit, push or deployment performed.

## Direction and diagnosis

The owner asked for “Projects I’m working on”, a shared visual language,
more room for animation and a more ambitious explanation of the projects.
The scope is the project section; routes, navigation anchors, professional
history, credentials and the rest of the portfolio remain in place.

The original 1440 px view had a 1088 px project panel about 939 px high, but
its screenshot was limited to 352 px wide. Switchboard mixed a tall capture
with a second replay below the copy; SIGEA had a placeholder, and Custodia
had a separate animation style. Automatic project rotation could also replace
the project being read.

Design: keep the current graphite palette, blue accent, self-hosted typography
and Astro/CSS. Expand the project section to an 88rem container, give the
scene most of the panel and use a common Today / What’s next checkpoint.
Design variance 6, motion intensity 5, visual density 4. Motion explains the
flow of information and decisions. No new dependencies or image service.

## Implemented

- `ProjectShowcase.astro`: explicit project selection with keyboard-compatible
  tabs; no automatic project switching. Every project remains visible if
  JavaScript is unavailable.
- `ProjectScene.astro`: shared responsive diagram and three-step replay,
  with pause/play and manual step selection. Playback stops off screen or
  when the document is hidden. Reduced motion stops continuous playback,
  including when that preference changes while the page is open.
- Switchboard: identity and route requirements feed an access decision, with
  allow, refuse and fresh-authentication outcomes. This is an explanation
  using example people, not a login to a real application.
- SIGEA: compare two complete captures of the same documentation-only host;
  identify a newly observed service and a service no longer observed. The
  explanation explicitly says a partial capture would not justify retirement.
  This is an illustration of the workflow, not evidence of v2 product parity.
- Custodia: independent CyberArk and Netskope records, a unique-email link
  and a conclusion supported by the rule. Client-signal coverage is not
  described as proof of all endpoint protection. Go, verified gateway identity
  and more adapters are described as next work.
- Content is coherent in EN and ES, including Custodia. The three projects
  use the same composition; illustrations and current capability remain
  distinct in the copy.

The old `DecisionDemo.astro` and `CustodiaStory.astro` renderers and their
unused replay styles were replaced by the shared scene. The original
Switchboard screenshot asset remains available, but is not used in this block.

## Verification and review

Build: `npm run build` (Astro diagnostics and both static routes), zero errors,
warnings or hints. Final browser verification: 30 layout combinations,
six axe audits with zero violations and zero incomplete checks, keyboard
selection, playback/pause, live reduced-motion changes and both languages
without JavaScript. Browser evidence, measurements and accessibility JSON live
in `../../reviews/portfolio-projects-2026-10-22/`; the report records limits.
At 1440 px the panel is 1342 px wide and about 740 px high, with an 849 px
scene instead of the old 352 px screenshot.

An initial 320 px check found an internal two-pixel overflow: the pause label
and numbered steps competed with the scene heading. The label and narrow-screen
controls were adjusted. The first accessibility pass also identified a missing
group role on the step controls; it was corrected.

The project links are existing destinations from the content and project
trackers. This local review does not re-certify public deployment availability.
Automatic accessibility results do not constitute a full WCAG certification.
